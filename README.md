# ydisk-web-backup — выкачать весь Яндекс Диск через веб-версию

Скрипт скачивает **все файлы с Яндекс Диска на ваш компьютер** через веб-версию: сам обходит папки, сам «нажимает Скачать» на каждом файле, докачивает оборванное, запоминает, что Яндекс отдать не смог, и при повторном запуске добирает только недостающее.

Пригодится, если другие способы не подходят:
- приложение Яндекс Диска ставить не хочется,
- REST API Диска отвечает `410 Gone`,
- WebDAV доступен только на платном тарифе,
- веб-версия отдаёт файлы **только по одному**.

Ничего от Яндекса на компьютер не ставится. Используются ваш Google Chrome (или встроенный Chromium) и Python.

> **Если у вас есть ИИ-ассистент** (Claude Code, Cursor, Codex, Copilot и т.п.) — просто откройте эту папку в нём и скажите: «Установи и запусти по инструкции из AGENTS.md». Он всё сделает сам, а вам останется один раз войти в Яндекс в открывшемся окне.

---

## Что нужно

- macOS, Linux или Windows
- Python 3.10+ (`python3 --version`; macOS: `brew install python@3.12`)
- Google Chrome или Microsoft Edge — желательно; если нет, установщик скачает встроенный Chromium (~150 МБ)
- Свободное место на диске: столько, сколько занято на Яндекс Диске (смотрите в веб-версии внизу слева)
- Доступ к аккаунту Яндекса в браузере (логин/пароль/SMS — всё вводите вы сами в окне браузера; скрипт паролей не видит и не хранит)

## Установка

```bash
cd ~
git clone https://github.com/eromanovvv/ydisk-web-backup.git ydisk-web-backup
cd ydisk-web-backup
./setup.sh
```

Клонируйте в домашнюю папку (`~/ydisk-web-backup`), а **не** в «Документы», «Рабочий стол», «Загрузки» или папку iCloud Drive / OneDrive / Dropbox. В папке репозитория будет лежать сессия Яндекса (см. «Безопасность»), и облако не должно её синхронизировать. Кроме того, на macOS фоновые задачи (ночной прогон) не могут читать «Документы», «Рабочий стол» и «Загрузки».

`setup.sh` создаёт виртуальное окружение `.venv`, ставит [Playwright](https://playwright.dev) (библиотека управления браузером от Microsoft) и при отсутствии Chrome — встроенный Chromium. Больше ничего в системе не меняет.

## Запуск

```bash
.venv/bin/python ydisk-web-backup.py
```

1. Откроется **отдельное окно браузера** с чистым профилем. Войдите в нём в аккаунт Яндекса.
2. Как только появится список файлов Диска, скрипт сам подхватит сессию, просканирует все папки (включая «безлимитные» фото с телефона) и начнёт скачивать.
3. Файлы кладутся в `~/YandexDisk-Backup/default/` с той же структурой папок, что на Диске (`disk/…` — обычные файлы, `photounlim/…` — безлимитные фото).
4. В конце — сводка: сколько скачано, сколько не удалось, и файл со списком отказов.

Окно браузера во время работы закрывать нельзя, компьютер не должен уснуть. Можно свернуть.

### Повторный запуск

Та же команда. Уже скачанные файлы пропускаются, оборванные — докачиваются с места обрыва, недоступные пробуются снова. **Если часть файлов Яндекс временно не отдаёт, запускайте раз в день-два, пока список отказов не опустеет.** Ничего с Диска до этого не удаляйте.

### Полезные параметры

```
--profile ИМЯ       отдельный профиль браузера на каждый аккаунт (по умолчанию default)
--dest ПАПКА        куда складывать (по умолчанию ~/YandexDisk-Backup/<профиль>)
--workers N         параллельных загрузок (по умолчанию 6; при большой доле ошибок ставьте 10)
--scan-only         только составить список файлов и показать объём, ничего не качать
--no-rescan         не сканировать заново, взять прошлый список (быстрее при повторах)
--roots /disk       только обычные файлы, без безлимитных фото (по умолчанию и /disk, и /photounlim)
--browser chromium  принудительно встроенный Chromium (по умолчанию auto: Chrome → Edge → Chromium)
```

Два аккаунта (например, свой и близкого человека):
```bash
.venv/bin/python ydisk-web-backup.py --profile masha --dest ~/Backups/Masha
.venv/bin/python ydisk-web-backup.py --profile petya --dest ~/Backups/Petya
```
Каждый профиль — своё окно и своя сессия; можно запускать параллельно.

## Что лежит в папке назначения

```
~/YandexDisk-Backup/default/
├── disk/                      файлы Диска с исходной структурой папок
├── photounlim/                безлимитные фото с телефона (если есть)
└── _backup-state/
    ├── manifest.json          полный список файлов Диска (путь, размер, дата)
    ├── failed-ДАТА-ВРЕМЯ.txt  что не удалось в этот запуск: путь, размер, причина
    └── api-calls.log          технический лог запросов (для разбора проблем)
```

Недокачанные файлы лежат как `имя.part` — это нормально, они докачаются в следующий раз.

## Причины отказов и что они значат

| В `failed-*.txt` | Что это |
|---|---|
| `timeout: хранилище Яндекса не отвечает` | Яндекс выдал ссылку, но сервер с файлом не ответил. Файл временно недоступен. Пробовать позже. |
| `размер X != ожидалось Y` | Оборвалось на середине. Кусок сохранён (`.part`), в следующий раз докачается. |
| `HTTP 500 / 502 / 503 / 504` | Ошибка на стороне Яндекса. Пробовать позже. |
| `HTTP 404 / 410` | Файла нет (удалён или переехал). |
| `нет ссылки` | Яндекс не выдал ссылку — обычно слетела сессия; перезапустите и войдите заново. |
| `небезопасное имя — пропущен` | Имя файла на Диске такое, что файл записался бы вне папки назначения (например, `..`, а на Windows — `\` или `:`). Скачайте его вручную в веб-версии. |

## Как это работает (для любопытных)

Веб-версия Диска общается со своим сервером через внутренний API `disk.yandex.ru/models-v2`. Скрипт запускает браузер через Playwright и выполняет в странице те же запросы, что и сама веб-версия: `mpfs/resources` (список папки, до 1000 элементов за раз) и `mpfs/url` (подписанная ссылка на скачивание с `downloader.disk.yandex.ru`). Ссылки скачиваются уже из Python, без cookies, параллельно, с `Range`-докачкой. Браузер нужен только из-за сессии (cookies) и CSRF-ключа `sk` — их никто никуда не экспортирует, они остаются внутри профиля браузера в папке `chrome-profile/`.

Почему не проще: у страницы Яндекса жёсткий CSP, который запрещает ей обращаться к `localhost`, поэтому вариант «скрипт в странице + локальный сервер» не работает; REST API отвечает `410 Gone`; WebDAV платный.

## Безопасность и приватность

- Пароль вы вводите только в окне браузера на сайте Яндекса; скрипт его не получает.
- Скрипт обращается только к Яндексу. Никакой телеметрии, никаких сторонних серверов.
- Скрипт ничего не удаляет и не меняет на Диске: только читает списки и скачивает.
- Сессия хранится в `chrome-profile/<профиль>/` внутри папки репозитория. **Копия этой папки — это вход в ваш аккаунт Яндекса**: на macOS и Linux cookies в ней не защищены системным хранилищем паролей. Поэтому:
  - не копируйте, не архивируйте и не коммитьте её (она в `.gitignore`);
  - не держите репозиторий в папке, которая синхронизируется с облаком (iCloud Drive, OneDrive, Dropbox, Google Drive).
- **Как выйти.** Просто удалить папку `chrome-profile/<профиль>/` мало: сессия на стороне Яндекса останется действующей, и любая уцелевшая копия папки (облако, Time Machine, резервная копия) продолжит давать вход. Правильно так:
  1. Откройте Яндекс ID → «Безопасность» → «Ваши устройства». Завершите сеанс этого браузера или нажмите «Выйти на всех устройствах» (в некоторых версиях кнопка называется «Выйти везде»).
  2. Потом удалите папку `chrome-profile/<профиль>/`.
- **macOS: не выдавайте `/bin/zsh` «Полный доступ к диску».** Такой доступ получит любой zsh-скрипт на компьютере, а не только этот. Если ночной прогон не может прочитать скрипт, перенесите репозиторий из «Документов», «Рабочего стола» или «Загрузок» в `~/ydisk-web-backup`.
- **Если пользуетесь ИИ-ассистентом**: он видит вывод скрипта — ваш логин Яндекса и названия папок — и передаёт их своему провайдеру (Anthropic, OpenAI и т.п.). Открывать сами файлы ему не нужно, и `AGENTS.md` это запрещает.
- Это неофициальный способ. Формально автоматизация веб-версии может противоречить условиям использования Яндекса. Автор пользовался им для выгрузки своих файлов; делайте выводы сами.

## Ограничения

- Корзина и старые версии файлов не выгружаются (их нет в дереве Диска). Если нужны — восстановите их в веб-версии до запуска.
- Общие папки (расшаренные вам другими) выгружаются, если они видны в вашем дереве.
- Скорость ограничивает Яндекс, а не скрипт.
- `md5` Яндекс в листинге не отдаёт, поэтому проверка — по размеру файла.

## Автоматический ночной прогон (macOS)

В `extras/macos-nightly/` — скрипт и установщик агента launchd, который запускает выгрузку каждую ночь и к утру кладёт отчёт в текстовый файл. Репозиторий для этого должен лежать вне «Документов», «Рабочего стола» и «Загрузок» (например, `~/ydisk-web-backup`). См. `extras/macos-nightly/README.md`.

## Windows

```powershell
cd ~
git clone https://github.com/eromanovvv/ydisk-web-backup.git ydisk-web-backup
cd ydisk-web-backup
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python ydisk-web-backup.py
```
Если Chrome не установлен: `.venv\Scripts\python -m playwright install chromium`.

Папка `~` в PowerShell — это `C:\Users\<вы>`. OneDrive её не синхронизирует (он синхронизирует «Документы» и «Рабочий стол», если включено резервное копирование папок), поэтому клонируйте именно туда.

## Если REST API Диска снова заработает

Тогда проще `rclone` (backend `yandex`): `rclone copy ydisk: ~/YandexDisk-Backup --transfers 4 --retries 3`. В `extras/rclone-api.sh` — готовый скрипт с логами и списком ошибок. На момент написания API отвечает `410 Gone`.
